# Шаблон протокола и полной расшифровки встречи

Готовый переносимый пакет. Скопируйте папку целиком в любой проект. Связи с исходным проектом, учетными записями и внешними сервисами нет.

Главный файл — **template.docx**, версия с правками владельца. Документ начинается непосредственно с части I; после протокола с новой страницы идет полная дословная расшифровка. Файл не пересобран и не изменен при упаковке.

## Что лежит в папке

| Файл / папка | Назначение |
|---|---|
| template.docx | Эталон Word с 87 полями для заполнения |
| template.md | Текст исправленного шаблона для чтения человеком и ИИ |
| fields.json | Справочник полей: имя, подпись, раздел и группа |
| data.schema.json | JSON Schema входных данных для редакторов и других проектов |
| docs/formatting.md | Самодостаточные правила оформления |
| docs/filling-rules.md | Правила протоколирования и полной расшифровки |
| docs/filler-usage.md | Команды заполнителя и формат входного JSON |
| docs/owner-changes.md | Учтенные правки владельца и происхождение формы |
| scripts/fill_template.py | Автономное заполнение копии DOCX |
| scripts/verify_package.py | Проверка целостности комплекта |
| examples/data.example.json | Учебные входные данные, не реальная встреча |
| examples/filled.example.docx | Заполненный учебный пример для проверки процесса |
| fonts/ | PT Serif Regular / Bold и лицензия |
| tests/ | Проверки заполнителя |
| manifest.json | Контрольные суммы файлов комплекта |

## Начать без программирования

1. Установите шрифты из fonts/ на компьютере, где будете открывать документ. В macOS и Windows откройте каждый TTF и выберите установку шрифта. На Linux используйте штатный менеджер шрифтов своей системы.
2. Откройте копию template.docx в Word или совместимом редакторе.
3. Заполните поля, повторите карточки участников, решений, поручений и реплик. Правила — в docs/filling-rules.md.
4. Сохраните результат под новым именем. Эталон оставьте неизменным.

## Заполнить программно

Нужен только Python 3.10 или новее. Пакеты pip, Docker, Kubernetes, доступ в интернет и API-ключи не требуются. Для открытия DOCX нужен совместимый редактор; Python создает файл без установленного Word.

Из этой папки:

```bash
python3 scripts/verify_package.py
python3 scripts/fill_template.py --data examples/data.example.json --output meeting-example.docx
python3 -m unittest discover -s tests -v
```

В Windows команда Python может называться `py -3` вместо `python3`. Выходной файл должен иметь новое имя: заполнитель не перезаписывает существующие документы.

Учебный JSON замените своими данными. Для нескольких участников, задач и реплик используйте списки blocks, описанные в docs/filler-usage.md. Скрипт переносит готовый текст; распознавание аудио и принятие решений за участников в него не входят.

## Передать другому ИИ-проекту

Передайте целиком эту папку и такое задание:

> Прочитай README.md, docs/filling-rules.md, docs/formatting.md и docs/filler-usage.md. Используй template.docx как эталон оформления и fields.json как справочник. По предоставленным материалам подготовь входной JSON и создай новый DOCX через scripts/fill_template.py. Сначала протокол, затем полная дословная расшифровка. Сохрани пользовательские правки и не выдумывай сведения. Эталон не меняй. Отсутствующие данные и пропуски записи обозначь явно.

## Обновление формы

Меняйте копию template.docx. После согласования новой версии обновляйте текстовую копию, справочник полей и контрольные суммы, затем запускайте тесты. Для нового состава повторяемых карточек понадобится изменить их границы в заполнителе. Он предназначен для структуры этой формы, а не для произвольных документов Word.

Изменение template.docx без обновления manifest.json будет обнаружено проверкой целостности. Проверка целостности не подтверждает правильность содержания встречи и не заменяет просмотр готового документа.

Пакет не устанавливает навыки или конфигурации в другие проекты автоматически и не отправляет данные наружу.
