# Обновление iriz

Этот навык обновляет уже поставленную копию. Первая установка - `/iriz-setup`, другой разговор.

Он работает там, где есть исходники: клон репозитория или распакованный ZIP. Ставили готовым образом из Releases - обновление выглядит иначе, и об этом внизу отдельно.

## Правила

**1. Сначала показать, потом делать.** Сказать, какая версия стоит сейчас и какая опубликована, и показать список изменений. Решает человек, а не я.

**2. Грязное дерево - стоп.** Есть незакоммиченные правки - назвать эти файлы поименно и остановиться. Чужую работу не затираем.

**3. Только вперед.** Тянуть `--ff-only`. Разошедшуюся историю не чинить силой: показать, объяснить простыми словами и дать выбрать.

**4. Не трогать твое.** Обновление не касается ничего из этого, и сказать это надо вслух до начала, а не после:

- настройки и переназначенные клавиши (`defaults`, домен `ru.iriz.app`);
- расшифровки в `~/Library/Application Support/iriz/dictations/`, включая `raw.txt`;
- словарь замен, счетчики, снимок выданных разрешений;
- скачанная модель распознавания в кэше `FluidAudio`: полгигабайта заново не поедут.

**5. Разрешения переживают пересборку.** Подпись остается той же личностью с тем же идентификатором бандла, и macOS считает приложение прежним. Заново выдавать микрофон, универсальный доступ и мониторинг ввода не придется. Если система вдруг спросила снова, это не норма, и сказать об этом надо прямо.

**6. Проверить себя после.** Прогнать проверку проекта и назвать результат как есть, включая красный.

**7. Не оставлять половину.** Собралось, но не поставилось; поставилось, но тесты красные - это незаконченное обновление, а не «почти получилось». Сказать простыми словами, что делать дальше, и оставить рабочую копию в состоянии, из которого программа запускается.

## Ход обновления

```bash
cd ~/iriz                       # или туда, куда ты его клонировал
git status --short              # твои правки, если они есть
git fetch && git log --oneline HEAD..@{u}   # что изменилось наверху
git pull --ff-only
bash install.sh --build
bash scripts/selfcheck.sh --selftest
swift test
```

Что человек увидит по порядку: свои несохраненные правки, если они есть; список того, что изменилось наверху; сборку; две проверки.

Сборка останавливает работающую программу и обратно ее не поднимает. Сказать это до запуска: значок пропадет из строки меню, и запустить приложение после обновления надо самому.

Пока идет сборка, сказать вслух, что появилось нового. Одной строкой на пункт, без «читайте историю коммитов».

## Если обновление не проходит

- **Есть локальные правки.** Назвать файлы и предложить два пути: закоммитить свое или отложить обновление. Не выбирать за человека.
- **История разошлась.** Объяснить простыми словами: у тебя есть коммиты, которых нет наверху. Показать варианты и дать решить.
- **Сборка не удалась.** Первая подозреваемая - не программа, а машина: обновленный Xcode, пропавшие Command Line Tools, версия Swift старше нужной. Назвать конкретную строку ошибки.
- **Проверка красная после обновления.** Назвать файл и строку, а не «что-то сломалось». Предложить откат на прежнюю версию одной командой и показать ее.

## Ставили готовым образом

Тогда репозитория на машине нет и тянуть нечего. Обновление здесь ручное: взять свежий `.dmg` в разделе Releases, закрыть работающую программу через пункт меню, перетащить новый значок в `Applications` с заменой.

Сказать заранее две вещи. Скачанная сборка снова покажет окно про непроверенное приложение, потому что метку macOS вешает на каждый новый файл из сети. Модель распознавания, расшифровки и настройки лежат вне бандла и остаются на месте: заново качать полгигабайта не нужно.

Обновление, о котором человек узнал постфактум, - плохое обновление. Все, что делается, объявляется заранее.
