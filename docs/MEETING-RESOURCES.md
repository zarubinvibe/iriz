# Пакет шаблона протокола внутри приложения

Исходный комплект хранится в `Sources/IrizDictate/Resources/MeetingMinutes` без изменений. `Package.swift` включает его через `.copy("Resources/MeetingMinutes")` в `IrizApp_IrizDictate.bundle`.

Установленное приложение и приложение внутри DMG содержат один и тот же путь:

```text
iriz.app/Contents/Resources/IrizApp_IrizDictate.bundle/MeetingMinutes/
```

Весь комплект переносится целиком: DOCX-шаблон, `fields.json`, `data.schema.json`, manifest, документация, примеры, тесты, вспомогательные скрипты и PT Serif с лицензией OFL. `scripts/build_app.sh` и `scripts/make_release.sh` сохраняют существующее копирование всех соседних SwiftPM-бандлов. Новый обязательный ресурс не заменяет языковой `IrizApp_IrizCore.bundle`.

Оба сборщика останавливаются, если комплект отсутствует, содержит симлинк, обязательный файл пуст или отсутствует, либо изменён шаблон. Проверка повторяется в установленном кандидате и в смонтированном DMG. При отказе до замены установленное приложение не меняется; при отказе после замены действует существующий откат. Выпуск не попадает в `dist`, пока проверки образа не прошли.

## Работа без каталога сборки

`MeetingTemplate` ищет ресурс относительно bundle приложения или тестового модуля. Абсолютный путь разработчика к `.build` и `Bundle.module` не нужны для запуска упакованного приложения. В `Tests/IrizDictateTests/MeetingDOCXTests.swift` есть проверка отдельно перенесённого `.app`, у которого комплект есть только в `Contents/Resources`.

Экспорт DOCX выполняется Swift-кодом с системным `/usr/bin/ditto` для ZIP-контейнера. Вложенные `scripts/*.py` и `tests/*.py` — часть исходного комплекта для ручной проверки; приложение их не запускает. Python не является runtime-зависимостью экспорта. Это не отменяет существующее использование Python самим release-сборщиком на машине разработчика или CI.

## Регрессии упаковки

```bash
bash scripts/build_app_test.sh --selftest
bash scripts/make_release_test.sh --selftest
```

Моки работают в собственных временных каталогах, не используют общую `.build`, не подписывают настоящий код, не монтируют образы и не обращаются к `/Applications`. Проверяются полный перенос комплекта и отказы при его потере или изменении. Реальную упаковку нового комплекта и экспорт из скопированного приложения нужно проверить отдельно; зелёный CI baseline 0.2.1 до этой интеграции их не подтверждает.
