# Сборка релиза для macOS

[English](RELEASING.md) · [Русский](RELEASING.ru.md) · [简体中文](RELEASING.zh.md)

Путь пользователя начинается со [страницы загрузки](DOWNLOAD.ru.md). Эта страница предназначена для сопровождающих проекта. Сборщик релиза не останавливает и не заменяет уже установленное приложение.

## Одна версия, два имени файла

`RELEASE_VERSION` - источник номера версии для локальной установки и сборки релиза. Укажи числовую версию в формате `major.minor.patch`, например `0.2.1`, и добавь проверенное описание в `docs/releases/v<version>.md`.

По умолчанию сборка предназначена для Apple Silicon и macOS 14+. Она создаёт:

| Файл | Назначение |
|---|---|
| `iriz-<version>-arm64.dmg` | Файл с номером версии для архива и отката |
| `iriz-macos-arm64.dmg` | Стабильное имя файла, которое использует кнопка в README |
| `SHA256SUMS.txt` | SHA-256 образов и манифеста |
| `release-manifest.json` | Коммит исходного кода, признак незакоммиченных изменений, версия, статус подписи и хеши образов |

Оба образа побайтно совпадают. GitHub поддерживает [ссылку на файл последнего релиза](https://docs.github.com/en/repositories/releasing-projects-on-github/linking-to-releases), поэтому каждый опубликованный релиз должен сохранять файл со стабильным именем. Не назначай черновик последним релизом, пока все его файлы не готовы.

## Локальная сборка и проверка

Используй Xcode 26.6 (сборка 17F113), его macOS 26 SDK и Swift 6.3.3: это инструменты релизной сборки. Приложение по-прежнему требует macOS 14+, но для компиляции интерфейса macOS 26 с проверками доступности нужен новый SDK. Xcode 26.3 не смог проверить типы в двух выражениях для подсказок; одной проверки версии Swift недостаточно. Зависимости берутся из `Package.resolved`.

Чтобы собрать релиз без сертификата подписи и автоматизации Finder, выполни:

```bash
swift test --no-parallel
bash scripts/make_release_test.sh --selftest
bash scripts/build_app_test.sh --selftest
ruby scripts/macos_release_workflow_test.rb --selftest
SMLTLK_SIGN_IDENTITY=- IRIZ_DMG_HEADLESS=1 bash scripts/make_release.sh
cd release/dist
shasum -a 256 -c SHA256SUMS.txt
```

`-` означает подпись ad hoc, а не подтверждённого издателя. Обычный локальный режим использует существующий сертификат самоподписи и окно Finder со стрелкой установки. Для отрисовки фона в этом режиме нужен Pillow; в режиме без интерфейса он не нужен. В обоих режимах образ содержит одно и то же приложение и ярлык Applications.

Полный набор тестов проверяет русский текст интерфейса и нативное сопоставление клавиш для английской и русской раскладок. Для этих проверок нужны соответствующий язык теста и включённые источники ввода Apple: это не модульные тесты, независимые от локали. CI готовит эти условия на одноразовом раннере. Не запускай режим настройки в своей учётной записи.

Сборки находятся в `release/build`, результат - в `release/dist`. Оба каталога исключены из Git. Не запускай сборщик релиза одновременно с локальным установщиком: они используют общий отрисовщик значков. Каталоги для временных файлов и результата должны оставаться внутри `release/` или `.build/` этого checkout и не должны содержать символьные ссылки.

Сборщик проверяет архитектуры приложения и фреймворков, минимальные версии системы, языковые ресурсы, встроенные зависимости, подписи кода и смонтированный образ. Предыдущий результат сохраняется, пока новые образы не пройдут проверку. После неудачной сборки остаются журнал и промежуточный каталог для диагностики; сборщик отключает только смонтированный им образ.

Шаблон встречи - обязательный ресурс приложения, а не документация только для разработчиков. Оба сборщика проверяют полный комплект его файлов и хеш шаблона, в том числе внутри смонтированного DMG. Для релиза с изменениями функции встреч также запусти наборы тестов DOCX, расшифровки, генератора и архива, а затем проверь экспорт из скопированного приложения. Подробности - в [MEETING-RESOURCES.ru.md](MEETING-RESOURCES.ru.md). Старый успешный прогон CI не проверяет новый шаблон или новый путь экспорта.

Для экспериментальной универсальной сборки задай `IRIZ_RELEASE_VARIANTS='arm64 universal'`. Дополнительный срез `x86_64` проверяет упаковку, но не доказывает, что распознавание работает на Mac с Intel. Не называй его проверенной поддержкой Intel.

## GitHub Actions

Процесс **macOS release draft** запускается вручную или по тегу `v*` в этом публичном репозитории. В форках и приватном рабочем репозитории он не работает. Если тег есть, он должен совпадать с `RELEASE_VERSION`.

Стандартный ARM64-раннер `macos-26` использует Xcode 26.6, указанный в [манифесте образа раннера GitHub](https://github.com/actions/runner-images/blob/0af81b6d930d02b52941d584bee9214c4bc228c6/images/macos/macos-26-arm64-Readme.md#xcode). Предварительная проверка сверяет выбранные Xcode, Swift и macOS SDK до компиляции. Раннер запускает тесты, собирает образ без интерфейса с подписью ad hoc и загружает пять входных файлов релиза: четыре публичных файла и собранное описание. Отдельная задача проверяет их, а затем создаёт **черновик** ровно с четырьмя публичными файлами. Она не исполняет код репозитория с токеном на запись. Существующие релизы и файлы никогда не перезаписываются. Черновик не меняет кнопку загрузки.

Перед тестами настройка hosted-раннера включает встроенные английский и русский источники ввода и задаёт русскую языковую настройку самого iriz. Она не выбирает другую активную раскладку, не меняет язык системы, не выдаёт разрешения и не заменяет нативную карту клавиатуры фикстурой. Настройка отказывается записывать что-либо вне hosted-раннера GitHub для macOS. Если обязательное условие не выполнено, сборка останавливается до запуска тестов.

Чтобы проверить полную сборку уже опубликованной версии, выбери **Run workflow → build_only: true**. Запустятся тесты, сборка и проверка DMG, а все пять входных файлов будут загружены как артефакт Actions. Собранное описание - это входной файл, а не публичный asset. Задача, которая пишет релиз, будет пропущена полностью: без черновика, тега, файлов и смены Latest.

При значении `false` уже опубликованный релиз завершается успешным no-op только в том случае, если его точная ссылка на тег разрешается в коммит, из которого сделана сборка. Это относится и к аннотированным тегам. В журнале появляется `already published, left unchanged`; процесс не редактирует релиз и не загружает файлы. При этом существующие файлы не проверяются: решение о приёмке всё равно зависит от независимой загрузки и проверки установки.

Существующий черновик, несовпадающая ссылка или исходный коммит, неверный ответ API либо ошибка API останавливают задачу без записи. Если релиза ещё нет, задача создаёт только новый черновик и не перезаписывает файлы.

Сопровождающий проверяет черновик, описание релиза и установку на чистой машине, запускает проверки публикации, а затем публикует релиз. Публикация - отдельное действие. Для этого процесса не нужны учётные данные Apple, а приложение не устанавливает фоновый обновлятор.

Перед публикацией выполни пять проверок по порядку:

1. Скачай DMG из черновика.
2. Смонтируй образ и проверь его подпись.
3. Запусти скопированное приложение на английском и китайском языках.
4. Полностью пройди выдачу разрешений, установку модели и первую диктовку.
5. Сверь хеши публичных файлов с локальным результатом.

Не заявляй о проверке микрофона или Intel, если её не было.

После публикации процесс **App download** проверяет кнопки в README и без аутентификации скачивает все четыре публичных файла релиза. Он также запускается после подходящих изменений в `main` и вручную через **Run workflow**. Те же проверки можно запустить локально с Node 22.15 или новее:

```bash
node scripts/check_app_download.mjs --selftest
node scripts/check_app_download.mjs --local
node scripts/check_app_download.mjs
```

Проверка опубликованного релиза переходит по стабильной ссылке, сверяет оба полных DMG с размерами и дайджестами файлов GitHub, манифестом и `SHA256SUMS.txt`, а также сопоставляет исходный коммит в манифесте с тегом релиза. Она отклоняет лишние файлы, ответы HTML, неполные загрузки и смену Latest во время проверки. Запросы обращаются только к заданным хостам GitHub, проходят не больше пяти перенаправлений, делают две попытки и укладываются в общий срок десять минут. DMG проходят через SHA-256 потоком и не записываются на диск.

Успешная проверка подтверждает целостность анонимной загрузки. Установку, подписи, разрешения и первую диктовку всё равно нужно проверить на macOS, как описано выше.

## Developer ID и нотариальное заверение

Текущие публичные сборки не заверены Apple. Самоподписанная подпись и подпись ad hoc не равны подписи Apple Developer ID. Ни одна из них не доказывает, что Apple проверила приложение.

Для нотариального заверения сначала получи действующий сертификат **Developer ID Application** и самостоятельно настрой профиль связки ключей `notarytool`. Не добавляй сертификат, закрытый ключ или пароль в репозиторий. Сборщик принимает существующие идентификатор и профиль:

```bash
SMLTLK_SIGN_IDENTITY='Developer ID Application: YOUR NAME (TEAMID)' \
IRIZ_NOTARY_PROFILE=iriz-notary \
bash scripts/make_release.sh
```

В этом режиме приложение и образ отправляются в Apple. Сборщик подписывает вложенный код, приложение и DMG, использует защищённую метку времени, отправляет материалы через `notarytool`, прикрепляет билеты и проверяет Gatekeeper. Ошибка останавливает сборку. Контрольные суммы рассчитываются после прикрепления билетов. См. [руководство Apple по подписи для распространения](https://developer.apple.com/documentation/xcode/creating-distribution-signed-code-for-the-mac) и [руководство по упаковке](https://developer.apple.com/documentation/xcode/packaging-mac-software-for-distribution).

Перенос идентификатора в CI требует отдельной настройки учётных данных. Следуй [процессу GitHub с временной связкой ключей](https://docs.github.com/en/actions/how-tos/deploy/deploy-to-third-party-platforms/sign-xcode-applications), ограничь доступ к секретам и удали связку ключей после работы. Не выводи переменные окружения и не включай трассировку shell рядом с секретами.

## Использованные образцы

Проверено 13 сентября 2026 года:

- [VoiceInk](https://github.com/Beingpax/VoiceInk/blob/main/README.md) помещает загрузку перед инструкцией по сборке и сохраняет стабильное имя DMG. iriz использует такое же разделение.
- [Handy](https://github.com/cjpais/Handy/blob/main/README.md) разделяет загрузки по оборудованию и объясняет разрешения и локальные модели. iriz называет проверенную платформу и отдельную загрузку модели.
- [Руководство Whispering v7.11.0](https://github.com/EpicenterHQ/epicenter/blob/v7.11.0/apps/whispering/README.md) устанавливает модель до начала записи. Это ссылка на конкретную версию, а не описание текущей ветки main.

Общая визуальная система сохранена. Понятная загрузка, инструкции первого запуска, контрольные суммы и порядок отката отвечают на практические вопросы, с которыми пользователь настольного приложения приходит на страницу.
